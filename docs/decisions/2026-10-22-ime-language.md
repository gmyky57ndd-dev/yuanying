# 决策记录 — 输入法语言切换（2026-10-22）

- **状态**: 已关闭，不再在应用内处理（Won't Fix in-app）
- **相关**: ES-056（移除假 Toggle）、ES-059（可视区布局）、#50、#56、#67、#69
- **结论**: Gboard 的「更改键盘」弹层在 Android Chrome / WebAPK 上被系统收回；应用侧无权也无法控制系统输入法，停止投入。

## 1. 现象

在元婴 PWA（以及 Chrome 浏览器）里，点输入框弹出键盘后，点「拼音」会出现「更改键盘」弹层，约 0.3–0.5 秒后自行消失，无法选择 English (US)。在 Notepad Free 等原生应用中同样的弹层可以停留。

## 2. 排查与证据

| 日期 | 假设 | 改动 | 结果 |
|---|---|---|---|
| 10-21 | 缺少切换控件 | 恢复 中/EN 按钮 | 无效（只改 placeholder） |
| 10-21 | 按钮被隐藏 | 修复 `hidden md:hidden` | 无效 |
| 10-21 | `lang="zh-CN"` 锁定输入法语言 | 移除字段 `lang` | 无效 |
| 10-21 | 合成期重渲染导致失焦 | `composingRef` + 原生 `<textarea>` | 无效 |
| 10-21 | 页面禁止缩放导致 IME 不弹 | `user-scalable=yes` / `maximum-scale=5` | 键盘可弹出，弹层仍消失 |
| 10-21 | 布局重排打断弹层 | 移除 `interactive-widget`、暂停轮询重渲染 | 无效 |
| 10-21 | 焦点被抢 | 移除 `visibilitychange` blur、pointerup blur | 无效（日志显示焦点始终在 textarea） |
| 10-22 | 容器未跟随可视区 | ES-059：高度绑定 `visualViewport.height` | 键盘遮挡修复，弹层仍消失 |
| 10-22 | 是否应用代码导致 | 极简页 `/ime-test`（无轮询/无布局代码） | **同样失败** |

关键证据（Owner 录屏 10 fps 抽帧 + 页面诊断日志）：

- 弹层出现约 0.3–0.5 秒后消失，未选中任何选项；
- `focusin`/`focusout` 全程只有 textarea，焦点**从未丢失**；
- 同样的失败发生在没有任何业务代码的极简页面。

## 3. 决策

1. **不在应用内做任何输入法切换功能**。系统键盘的语言切换由用户自己完成（Gboard 空格键 / 地球仪键）。界面保留：无 中/EN 按钮。
2. **保留 ES-059 的可视区布局修复**——它解决了"输入框被键盘遮挡"，是有价值的产品修复，与弹层问题无关。
3. **归类为设备/系统层问题**，不是元婴的可修复缺陷；相关 issue 关闭，不再新建排查项。
4. **用户侧绕法**（写入帮助文档，不在代码里）：
   - Gboard 设置 → 语言 → 同时启用 English (US) 与 简体中文 → 打开"在空格键上显示语言切换键"，点空格直接切换；
   - 或安装其他输入法（SwiftKey / 搜狗）验证；
   - 或使用元婴的 ◉ 语音输入。

## 4. 经验教训

1. **先证明问题归属，再改代码**。这次先后修改了 9 个假设，直到极简页复现才证明不是应用代码。正确顺序应该是：先做最小复现页/第三方页面对照，再定位到具体层。
2. **假控件比缺失控件更糟**。中/EN 按钮只改 placeholder，制造了"功能存在"的错觉，反而延长了排查。
3. **系统能力不要假装拥有**。PWA 无法控制 IME；遇到系统级限制，应直接告知并给出绕法，而不是不断尝试 CSS/JS。
4. **日志要说人话**。`h`/`vv` 这种缩写导致 Owner 与 Dev 对同一份数据得出不同结论；日志应写清 `layoutViewport` / `visualViewport`。
5. **给 Owner 的验证步骤要可判定**。应提供"通过/失败"的单一判据，例如"弹层是否停留 2 秒"，而不是多组模糊描述。
6. **时间盒**。同类尝试超过 2 轮仍无进展，应停止改动、转为定位归属。

## 5. 影响与后续

- `core/system-manifest.md` 的「语言输入」章节已写明：元婴不控制输入法，无 Toggle 是设计。
- 不再为输入法问题创建跟踪项；若未来换用支持 IME 的原生壳（如 Capacitor WebView 定制），再重新评估。
