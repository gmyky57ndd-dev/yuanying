# 调研报告：司书 / 个人图书馆 —— 资料库形态与 Obsidian 定位 (Issue #196)  (草稿 v0.1, 待 Owner 确认)  --  ## 1. Obsidian 定位：三种可能的取舍  | 方案 | 核心逻辑 | 优点 | 缺点/风险 | 结论 |  |---|---|---|---|---|  | **A. 同步层** (Obsidian = 真相源，元婴只读) | `local_kb/raw/` 指向 Obsidian Vault；元婴只建索引、只读 | - 零迁移成本，Owner 现有工作流不变  - 版权/隐私天然隔离（本地）  - 复用 Obsidian 生态（插件、图谱、Canvas） | - 耦合 Obsidian 格式（frontmatter、wikilink、Canvas JSON）  - 多 Vault / 多设备同步冲突由 Owner 自理  - 元婴无法写入「洞察/总结」回 Vault | **首选**  |  | **B. 编辑器** (Owner 在 Obsidian 写，元婴消费+写回) | 双向同步：元婴把摘要/标签/关联写回 Vault | - 知识闭环在同一地 | - 冲突解决极难（并发编辑、移动文件、删除）  - 需要文件锁/事件总线，工程成本高  - 破坏「本地优先、只读索引」架构红线 | **排除**  |  | **C. 格式借用** (只用 Markdown + wikilink 约定，不依赖 Obsidian) | `local_kb/raw/` 独立目录，约定 frontmatter + `[[wikilink]]` | - 完全解耦，元婴可控  - 方便未来换编辑器 | - 丢失 Obsidian 图谱/Canvas/插件生态  - Owner 需维护两套目录或单向导入 | **备选**（若 Owner 明确不想绑定 Obsidian） |  **建议**：**采用方案 A（同步层）**。  - `local_kb/raw/` = 指向 Owner 现有 Obsidian Vault 的**软链接/绑定路径**（配置化，不硬编码）  - 元婴**只读**、**只建 FTS5 索引**（`index.db`），**不写入** Vault  - 司书检索命中时，返回 `file_path` + `line_range` + `snippet`，Owner 在 Obsidian 打开  - 若 Owner 要「元婴生成的洞察入库」，走「导出为 .md → Owner 手动放入 Vault」单向流，不做自动双向  ## 2. 四类资料归口表  | 类型 | 真相源 | 索引粒度 | 全文检索 | 保留策略 | 备注 |  |---|---|---|---|---|---|  | **项目文件** | `local_kb/docs/` (元婴产出) + GitHub `docs/` (规范) + `project_docs` (云端 PRD) | 文件级 + 段落级 | 是 | 永久（Git 史） | 与 Obsidian Vault **无关**；走现有 `local_kb/docs/` + GitHub 双轨  |  | **藏书** | 物理书/电子书文件（Owner 管理，不入 `raw/`） | 章节/笔记级 | 仅笔记全文 | 永久 | **不存书本文件**（版权/体积）。只索引 Owner 在 Vault 里写的**读书笔记**（约定 frontmatter `type: book_note`）  |  | **网页** | 原始 URL + 可选的单文件归档 | 页面级 | 归档文件全文 | 1 年自动过期（可配置） | 默认**只存链接+摘要**；需全文时 Owner 触发「归档当页」→ 存入 `raw/web/`  |  | **Video** | 原始链接 (B站/YouTube/本地路径) | 视频级 + 时间戳笔记级 | 仅笔记/字幕全文 | 永久 | **不存视频文件**。索引 Owner 的**观影笔记**（`type: video_note`）+ 可选字幕文件  |  ## 3. 检索预期：Owner 真实提问样本（5 条）  1. `「上周阿构在 ADR 里说的 FTS5 迁移方案在哪个文件？」` → 定位 `local_kb/docs/adr/006-fts5-migration.md` 第 34-58 行 2. `「我去年对《原子习惯》第 3 章的笔记里提到的『两分钟法则』原文」` → 定位 Vault `Books/原子习惯/Ch03.md` 对应段落 3. `「那个关于『采集器权限自检』的网页剪藏，大概 10 月中旬存的」` → 定位 `raw/web/2026-10-15-collector-permission.md` 4. `「BWP PRD 里定义的『项目切换器』验收标准原文」` → 定位 `project_docs/BWP_PRD_V3.md` 对应 section 5. `「上个月看的那个关于『Context Engineering』的视频，我记了哪些笔记？」` → 定位 Vault `Video/Context Engineering.md`  **最低标准**：每条检索返回 `{file_path, line_start, line_end, snippet, score}`，Owner 一键在 Obsidian/VS Code 打开。  ## 4. 本轮明确不做（排除项）  - ❌ 双向同步（元婴写回 Vault）  - ❌ 图谱可视化/Canvas 解析  - ❌ 多 Vault 冲突解决  - ❌ 电子书全文入库 / 视频文件入库  - ❌ 网页自动定时归档（仅手动触发）  - ❌ 权限模型（与 #176 合并后再做）  - ❌ 多模态检索（图片/音频理解）  - ❌ 向量检索（本轮只做 FTS5 全文，向量留后续 ADR）  ## 5. 最小可行范围（MVP，端到端跑通一条链路）  1. **配置**：`local_kb/config.json` 新增 `vault_path`（指向 Owner Obsidian Vault 根目录） 2. **扫描**：`trigger_reindex` 遍历 `vault_path` 下所有 `.md`，提取 frontmatter + 正文 → 写入 `index.db` (FTS5) 3. **检索 API**：`local_rag_search(query, opts?)` 返回命中片段 + 路径 + 行号 4. **司书工具**：`read_obsidian_vault(path, offset?, limit?)` 读取原文上下文 5. **验收**：对上述 5 条真实提问，司书能在 2 秒内给出可打开的定位  6. **不含**：UI、定时增量、向量、权限、双向写回  ## 6. 关键取舍总结  | 决策点 | 选择 | 理由 |  |---|---|---|  | Obsidian 角色 | 同步层（只读真相源） | 零迁移、本地优先、解耦写入风险 |  | 索引技术 | SQLite FTS5 (trigram) | 无外部依赖、中文三字符切分可用、可从 raw 完整重建 |  | 资料入库方式 | 约定 frontmatter `type` 分类 | 无侵入、Owner 现有笔记只需加字段 |  | 检索返回 | 路径+行号+片段 | 够用、不绑定编辑器 |  | 写回 Vault | 单向导出 .md，Owner 手动放入 | 避免冲突、保持本地优先 |  ## 7. 后续步骤（不在本轮）  1. 阿构出 ADR：确定 FTS5 schema、分词器、增量更新策略 2. DSH 实现 `trigger_reindex` 重写 + `local_rag_search` + `read_obsidian_vault` 3. 司书接入工具白名单，跑通 5 条验收问 4. Owner 实测 1 周，再决定是否上向量/权限/双向  --  *文档状态：草稿，待 Owner 确认后定版至 `docs/pm/research/196-library-obsidian-research.md`*
