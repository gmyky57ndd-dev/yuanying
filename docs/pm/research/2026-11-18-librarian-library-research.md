# 司书 / 个人图书馆：资料库形态与 Obsidian 定位 — 调研结论 v1.0 (2026-11-18) 由拓维 (AI-PM) 产出，供阿构出 ADR 参考。--## 1. Obsidian 定位：结论**格式借用（只用 Markdown + wikilink 约定，不依赖 Obsidian 应用本身）**。理由：- Owner 的真相源是 `~/yuanying/local_kb/raw/`（原始文件）与 `local_kb/docs/`（整理后文档），二者均为纯 Markdown 目录树，不需要 Obsidian 打开才能读写。- Obsidian 的同步、插件、Canvas、Graph View 等功能对元婴无增量价值；反而引入「必须装 Obsidian」的运维负担。- 保留 wikilink `[[...]]` 与 frontmatter 约定，便于 Owner 如需可随时用 Obsidian 打开同一目录，但元婴不把 Obsidian 视为运行时依赖。--## 2. 四类资料归口表| 类型 | 真相源 | 索引粒度 | 全文检索 | 保留策略 | 备注 ||---|---|---|---|---|---|| **项目文件** | `local_kb/docs/`（整理后） + GitHub `docs/`（规范/对外） | 文档级（每个 .md 一个 chunk） | 是 | 永久（Git 历史） | 与 `project_docs` 表互补：云端存 PRD/ADR，本地存草稿/私有 || **藏书** | `local_kb/raw/books/`（epub/pdf 原文） | 章节级（按 TOC 切分） | 是（章节） | 永久 | 版权文件不上云；仅本地索引元数据 + 章节文本 || **网页** | `local_kb/raw/web/`（单文件 HTML / Markdown 剪藏） | 页面级 | 是 | 1 年滚动清理（可配） | 失效链接保留快照；不做定时抓取 || **Video** | `local_kb/raw/video/`（仅笔记 + 链接，不存媒体文件） | 笔记级 | 否（只搜笔记） | 永久 | 体积太大，只存 `title, url, timestamp, summary, local_note.md` |--## 3. 检索预期：Owner 真实会问的 5 个问题1. 「上周阿构在 ADR 里怎么定 `fenshen_playbooks` 表的？」 → 命中 `local_kb/docs/adr/...md`，给出路径 + 相关段落。2. 「《原则》这本书第 3 章讲了什么？」 → 命中 `raw/books/Principles/chapter-03.md`，给出章节摘要 + 文件路径。3. 「那个关于 HealthConnect 权限的网页剪藏在哪？」 → 命中 `raw/web/healthconnect-permissions.md`，给出路径。4. 「上个月那个关于 Token Broker 的视频笔记里提到的 15min TTL 是哪个视频？」 → 命中 `raw/video/token-broker-notes.md`，给出视频标题/链接/时间戳。5. 「帮我把最近三个月所有提到『步数』的笔记、ADR、藏书片段汇总一下」 → 跨四类混合检索，按时间倒序返回路径 + 片段。**最低标准**：每条结果必须包含 `source_path`（相对 `local_kb/` 的相对路径）与 `snippet`（≤300 字），Owner 点一下能打开原文。--## 4. 本轮明确不做- 不建「统一向量库」把所有类型混嵌一起（先做精确 FTS5，向量后补）。- 不做自动抓取/同步（网页、视频全靠 Owner 手动放入 `raw/`）。- 不做权限模型（私人资料全本地，#176 另讨论）。- 不做 Obsidian 插件/同步协议。- 不做「图谱/关联推荐」（先能搜到再谈关联）。--## 5. 最小可行范围（MVP）能跑通**一条端到端链路**：1. `local_kb/index.db` 为 **SQLite FTS5**（中文 trigram 分词），覆盖 `raw/` 与 `docs/` 所有 `.md/.txt`。2. `trigger_reindex` 工具：删库 → 遍历 `raw/` 与 `docs/` → 写入 FTS5，幂等可重跑。3. `local_rag_search(query, scope?)` 工具：受限于 `local_kb/`，返回 `{path, snippet, type}`。4. 司书分身只暴露 `local_rag_search` + `read_local_file`，**不写、不删、不改**索引。5. Owner 在 PWA / Desktop Hub 里 `@司书 找...` → 司书调用工具 → 返回路径与片段 → Owner 点开阅读。--## 6. 给阿构的 ADR 范围（仅此四项）1. **Library Root**：`~/yuanying/local_kb/` 为唯一根；`raw/` 只读原始，`docs/` 只读整理，`index.db` 可删可重建。2. **元数据 Schema**：FTS5 虚表 `chunks(rowid, path, type, title, content, mtime)` + 普通表 `files(path PK, type, mtime, size, hash)` 用于增量判断。3. **检索 API**：`local_rag_search(query, {type?, limit?})` → `{results: [{path, type, title, snippet, score}]}`。4. **Obsidian 边界**：单向只读——元婴不写 `.obsidian/`，不依赖其任何插件/格式扩展；Owner 如需可自行 `ln -s` 或在 Obsidian 里打开同一目录。--## 7. 关键取舍记录| 议题 | 取舍 | 理由 ||---|---|---|| 分词器 | **trigram (unicode61)** 而非 jieba | FTS5 内置、零依赖、中文召回率可接受；jieba 需编译扩展、部署麻烦 || 向量检索 | **暂缓** | FTS5 先跑通精确检索；向量加 embedding 模型、维度、存储成本，属 Phase 2 || 增量索引 | **mtime + hash 双判断** | mtime 快但不可靠（复制/同步会变）；hash 准但慢；先比 mtime，变了再算 hash || 索引频率 | **手动触发 / 每日一次上限** | `raw/` 变动低频；Owner 显式 `trigger_reindex` 即可，不做文件监听 || 跨类型混排 | **不做** | MVP 只按 `type` 过滤；混排排分需向量或 reranker，留 Phase 2 |--## 8. 后续动作- 阿构：基于本文档出 ADR（仅限第 6 节四项）。- DSH：按 ADR 实现 FTS5 schema、trigger_reindex、local_rag_search。- 司书：拿到工具后只做检索代理，不碰索引构建。--*文档结束*
