# ADR-006: Token Broker — 分身权限物理隔离 (v0.2, 2026-11-16 22:03 裁定版本) 此版本取代 mailbox 旧稿，以 Supervisor 22:03 裁定为准。 ## 背景 多分身（小悟 / 拓维 / 阿构 / 司书 / DSH）共用一个 LLM API Key，权限泄漏风险： - 小悟不该能写代码 - DSH 不该能改身份 / 语气 / 价值观 - 任何分身不该能越权调用未授权工具 需要**物理隔离**：每个分身拿到的 token 只能调用自己的工具集，且 token 短期、可审计、可撤销。 ## 裁定结论 (Supervisor 22:03) 1. **自研**，不采用 octobroker（6 维里 3 条不满足：部署要 K8s、无审计格式、无 HA） 2. **Per-fenshen scope**：每个分身一组 scope，token 只能调用该 scope 内的工具 3. **TTL 15 分钟**，自动刷新，主动撤销立即生效 4. **审计日志**含 `issue_number`、`fenshen_id`、`tool_name`、`args_hash`、`result_ok`、`latency_ms` 5. **最小可行**：SQLite + 单进程，Owner 批准后再上 PostgreSQL / HA ## 架构 Token Broker (单进程, SQLite) ├── /issue (POST)  签发 token，入参：fenshen_id, issue_number, scope[] ├── /refresh (POST)  15 分钟自动刷新 ├── /revoke (POST)  立即撤销 ├── /audit (GET)   查询审计日志 └── /health (GET)  存活探针 Scope 定义（示例） - xiaowu: [chat, get_notes, get_conversation_records, get_summary, get_drive_doc, get_model_info, web_search, read_markdown, get_issue, add_note, scheduler, ingest_external_chat, query_external_chats, read_local_file, write_local_file, ask_external_agent] - ai_pm: [chat, get_project_status, get_github_issue, read_code_file, read_local_file, write_local_file, web_search, read_markdown, push_to_dev] - ai_architect: [chat, get_project_status, get_github_issue, read_code_file, read_local_file, write_local_file, web_search, read_markdown, write_code_file, git_commit, submit_pr] - dsh: [chat, get_project_status, get_github_issue, read_code_file, read_local_file, write_local_file, web_search, read_markdown, write_code_file, git_commit, submit_pr, run_terminal_command, run_test_suite] - librarian: [chat, get_project_status, get_github_issue, read_code_file, read_local_file, write_local_file, web_search, read_markdown, local_rag_search, read_obsidian_vault] ## 实现验收 1.
