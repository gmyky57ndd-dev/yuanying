# ADR-006: Token Broker — 分身权限物理隔离 (v2 修订版，含 octobroker 回退决策记录) 2026-11-15 批准执行 状态：已批准，实现中 1. 背景 多分身并行时，必须把「谁能调用什么工具」从代码层面物理隔离，不能靠提示词约束。 2. 方案对比 | 维度 | octobroker (外部) | 自研 Token Broker (内部) | |---|---|---| | 真实性 | 仅 1 个 contributor，半年无 release，License 不明 | 完全自控 | | 粒度支持 | 不支持 per-agent token，只能项目级 | 原生支持 per-fenshen token + scope | | 技术栈兼容 | 需要独立 Go 服务 + PostgreSQL，与 Next.js 网关不兼容 | TypeScript 原生，零新依赖 | | 部署成本 | 新增数据库、服务、监控、备份 | 复用现有 Supabase + Edge Function | | 审计能力 | 日志字段固定，无法记录 Actor/Target 细节 | 完全可定制审计表 | | 兜底风险 | 服务挂了全系统不可用 | 降级为静态白名单，核心链路不中断 | 3. 判定 任何一条不满足 → 直接回退自研。octobroker 四条不满足，决策：回退自研。 4. 自研 Token Broker 设计 4.1 核心表 fenshen_token (fenshen_id, token_hash, scopes[], expires_at, revoked_at) token_audit (actor_fenshen, target_fenshen, tool, scope, allowed, reason, ts) 4.2 颁发流程 1. Owner 在 Settings 生成 token → 仅存 hash，明文仅显示一次 2. scopes 例：ai_pm:read_issue,write_comment,assign_issue; dsh:read_code,write_code,push_pr 3. 过期默认 90 天，可撤销 4.3 网关拦截 所有 `/api/fenshen/*` 请求先过 Token Broker 中间件： - 验证 token 有效性 - 检查 scope 是否包含请求的 tool - 写审计 - 放行或 403 4.4 降级模式 Token Broker 不可用时，读取静态白名单 `config/fenshen-scopes.json`，仅允许核心分身（xiaowu, ai_architect, dsh）的只读操作。 5. 实现任务拆解 (给 DSH) 5.1 数据库迁移：建 fenshen_token, token_audit 表 + RLS 5.2 Edge Function `token-broker/verify`：验证 + 审计 5.3 中间件集成：`/api/fenshen/*` 路由挂载 5.4 Settings UI：生成/撤销 token、查看审计日志 5.5 静态白名单 `config/fenshen-scopes.json` 5.6 单元测试：过期/撤销/越权/降级 6. 验收标准 - ai_pm 能 comment_on_issue，不能 push_to_dev - dsh 能 read_code_file/write_code_file，不能 assign_issue - 无效 token 返回 403，审计可查 - Token Broker 进程杀掉，静态白名单生效，核心分身只读可用 7. 回滚方案 迁移脚本含 down migration；Edge Function 可单独回滚；静态白名单始终兜底。 8. 关联 Issue #176 (Epic), #196 (司书权限边界)
